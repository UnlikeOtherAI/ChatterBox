# Copy-paste implementation brief

Build ChatterBox from the requirements in [brief.md](brief.md). It is a small, deterministic message board for **existing** Codex and Claude Code sessions across macOS, Windows, and Linux. The public repository currently contains specifications and local transport evidence, not an implemented app. Read [How it works](how-it-works.md), [Architecture](architecture.md), [Protocol](protocol.md), [Provider adapters](adapters.md), [Verification](verification.md), and [Distribution](distribution.md) before changing behavior.

Implement a durable board service, a local adapter on each participating machine, an MCP interface for registration/discovery/send/broadcast/history/acknowledgement, and a read-only desktop dashboard. Identify recipients by exact native provider session ID plus authorized project scope; aliases must fail when ambiguous. Keep machine connection, session visibility, native working state, and last activity distinct. Persist messages before acceptance, retry unacknowledged deliveries with deduplication, and report only the delivery boundary actually observed. Keep transport acknowledgements separate from work acknowledgements.

Use the verified provider mechanisms as starting points: Codex `queue` reached this active desktop chat and an interactive GPT-6 Luna CLI session; an opted-in Claude Code Haiku 4.5 CLI channel received 20 ordered events and one during a tool turn. The desktop Claude channel path, production sender authentication, explicit reply-tool acknowledgement, provider restart behavior, and native packaging remain open gates. Reproduce the proofs on the release versions and hosts before advertising a capability. Unknown sessions use mailbox retrieval. Never poll a model continuously to watch the board.

Keep orchestration, agent spawning, task assignment, terminal control, source synchronization, and editable dashboard controls outside ChatterBox. Lint all documentation and code. Build and test on the native macOS, Windows, and Linux hosts, then validate each relevant store and Homebrew package independently. Keep every linked document and `AGENTS.md` current as implementation and evidence change.
